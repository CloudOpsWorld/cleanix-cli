# Cleanix Native GUI Implementation Plan (Plan 2A)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a native desktop GUI (`cleanix gui`, PySide6) with a Simple mode and a Power mode, backed by the existing engine, plus the elevated-helper flow for admin-only items.

**Architecture:** A thin, Qt-free service layer (`cleanix/core/service.py`) wraps `Engine`, history and quarantine so the GUI never re-implements scan/clean orchestration or safety. GUI code lives in `cleanix/gui/` and only imports PySide6 there; long work runs on worker threads. Admin-only items go through a small elevated helper process that receives item identifiers only, re-scans as admin and deletes only what matches.

**Tech Stack:** Python >= 3.10, PySide6 (optional extra `gui`), pytest + pytest-qt (extra `gui-test`), `QT_QPA_PLATFORM=offscreen` for headless tests.

**Spec:** `docs/superpowers/specs/2026-11-16-windows-and-gui-design.md` (Part 2 plus "Clarifications from the builder check"). This is Plan 2A; the standalone installers, signing and the release pipeline are Plan 2B (written after this plan ships).

## Global Constraints

- Python >= 3.10; base dependencies stay `rich` and `PyYAML`; the GUI is the optional extra `pip install "cleanix-cli[gui]"` (PySide6, LGPL). Importing `cleanix` or running any CLI command must never import PySide6.
- The GUI calls the engine in-process through `cleanix/core/service.py`. No second implementation of safety, scanning or removal. Deletion still goes only through `safe_rmtree`/`safe_unlink`.
- The GUI itself never runs as root/administrator. Only the elevated helper does, and it never trusts caller-supplied paths.
- Quarantine ("keep a copy so I can undo") is ON by default in the GUI.
- Simple mode pre-selects only deletable, low-risk items: never report-only items, never items needing admin, never irreversible command items, never the Trash/Recycle Bin, never personal-data categories.
- Existing CLI commands, flags and JSON output stay compatible; existing tests keep passing on Linux, macOS and Windows.
- GUI tests run headless (`QT_QPA_PLATFORM=offscreen`) and are skipped cleanly when PySide6 is not installed (`pytest.importorskip("PySide6")`).
- Version `1.4.0`. Work on branch `feat/gui`. Commit messages end with the line `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- Dev setup: `pip install -e ".[gui-test]" pytest`; run tests with `python -m pytest -q`.

## Review Focus

1. Cancelling a scan or clean mid-way (or closing the window) must stop cleanly: no frozen UI, no half-recorded history, no deletion after the cancel.
2. Simple mode must not pre-select report-only, admin, irreversible or personal-data items, even for a cleaner whose `safe_default` was never reviewed (default False).
3. A tampered, stale or foreign request given to the elevated helper (extra keys, a path key not present in its fresh scan, a request file owned by another user) must delete nothing outside the fresh scan.
4. The user declining the UAC/`pkexec`/macOS password prompt, or the helper crashing or timing out, must produce a clear message, still report the non-admin items already cleaned, and never hang the UI.
5. Very long paths, non-ASCII and right-to-left names, HiDPI and dark mode, and keyboard-only use: tables elide with tooltips instead of breaking layout, every control is reachable by Tab and has an accessible name.

## File Structure

- `cleanix/core/service.py` (new): scan/clean orchestration without UI (Task 1).
- `cleanix/core/catalog.py` (new): cleaner metadata, categories, Simple-mode pre-selection rule (Task 2).
- `cleanix/core/elevate.py`, `cleanix/elevated.py` (new): request/response + helper entry (Task 3); platform launchers (Task 4).
- `cleanix/gui/` (new package): `app.py`, `main_window.py`, `workers.py`, `simple_view.py`, `power_view.py`, `models.py`, `panels.py`, `reveal.py`, `elevation.py`, `theme.py`.
- `tests/gui/` (new): headless GUI tests with `tests/gui/conftest.py`.

### Task 3: Elevated helper (request, re-scan, match, clean)

**Files:**
- Create: `cleanix/core/elevate.py`, `cleanix/elevated.py`

**Interfaces:**
- Consumes: `service.scan`, `service.clean`, `models.item_key`, `context`.
- Produces in `elevate.py`:

  - `@dataclass HelperResult: freed: int; removed: int; errors: List[str]; unmatched: int`.
  - `write_request(directory: Path, selection: Selection) -> Path` (writes `request.json`, mode 0600 on POSIX; `directory` is created 0700 by the caller via `make_request_dir() -> Path` which uses a per-user private temp location).
